# 실시간 다국어 자막 시스템

로컬 네트워크에서 돌아가는 2인 협업 자막 입력 · 크로마키 송출 웹앱.
속기사가 입력한 자막이 송출용 화면에 실시간으로 뜨고, 그 화면을 스위처/가상카메라로 받아 방송에 합성한다.

빌드 도구 없음. `node server.js` 하나면 뜬다.

---

## 1. 빠른 시작

```bash
npm install
npm start
```

콘솔에 접속 주소가 찍힌다.

```
🚀 자막 중계 서버 기동
   호스트명 : studio-pc
   로컬 접속: http://localhost:3000
   외부 접속: http://192.168.0.11:3000   (en0)
```

**같은 네트워크의 다른 PC는 "외부 접속" 주소를 브라우저에 그대로 입력**하면 된다.
접속이 안 되면 서버 PC의 방화벽에서 3000 포트를 열어야 한다.

랜딩 페이지에서 언어별로 두 가지 화면에 들어갈 수 있다.

| 화면 | 주소 | 누가 쓰나 |
|---|---|---|
| 입력용 (Typist) | `/typist?lang=ko&name=속기1` | 속기사 |
| 송출용 (Broadcast) | `/broadcast?lang=ko` | 스위처에 물리는 화면 |

`lang`이 다르면 완전히 별개의 방이다. 한국어 방과 영어 방은 서로를 모른다.

## 2. 구성

```
server.js              Express + Socket.io 중계. 상태는 방별 최근 4줄 + 딜레이 값만 보관
config.json            언어 목록, 기본 딜레이, 송출 화면 기본 설정
public/
  index.html           랜딩 (언어 × 역할 버튼)
  common/
    socket-client.js   접속·재접속·신원(clientId)·RTT
    settings.js        송출 설정 해석 (URL > localStorage > config)
    i18n.js            UI 언어 (한국어/English)
  typist/              입력용 화면
  broadcast/           송출용 화면
scripts/
  smoke-socket.js      헤드리스 릴레이 검증   (npm run smoke)
  hotkey-rules-test.js 핫키 충돌 규칙 검증     (npm run test:hotkeys)
```

**큐 관리(줄 수·만료·최소 노출)는 전부 송출 화면 클라이언트가 한다.** 서버는 중계만 하므로,
서버를 재시작해도 이미 떠 있는 송출 화면이 깨지지 않고, 송출 화면을 여러 대 물려도 각자 독립적으로 렌더된다.

---

## 3. 언어 추가/변경

`config.json`의 `languages`만 고치면 랜딩 페이지에 자동으로 뜬다.

```json
"languages": [
  { "code": "ko", "name": "한국어" },
  { "code": "en", "name": "English" },
  { "code": "ja", "name": "日本語" },
  { "code": "zh", "name": "中文" }
]
```

언어를 추가하면 **그 언어용 속기사와 송출 화면을 따로 띄우면 된다.** 코드 수정 불필요.

## 4. 속기사 화면 사용법

### 단축키

| 키 | 동작 |
|---|---|
| `Enter` | 전송 |
| `Shift+Enter` | 줄바꿈 |
| `Esc` | 입력창에 글자가 있으면 → 입력창 비우기 / 비어 있으면 → **송출 자막 전체 숨김** |
| `Ctrl+Backspace` | 내가 방금 보낸 자막만 회수 (아직 대기 중이면 취소) |
| `Ctrl+Z` | 입력창 실행취소 (일반 텍스트 편집과 동일) |
| 사용자 지정 | 핫키 — 등록한 문구를 입력창에 삽입 |

### 전송 딜레이

슬라이더로 0~10초. **방 전체 공통값이라 두 속기사가 항상 같은 값을 본다.**
누군가 바꾸면 상대 화면의 슬라이더도 따라 움직이고 토스트로 알려준다.

딜레이를 1~2초라도 걸어두면 **오타를 화면에 내보내기 전에 잡을 수 있다.**
대기 중인 자막은 히스토리에 `송출 대기`로 뜨고 `취소` 버튼으로 없앨 수 있다.

### 핫키

입력창 위 `⚙ 핫키 설정`을 누르면 팝업이 뜬다. 키 칸을 클릭하고 원하는 조합을 누르면 등록된다.

- **안전한 조합**: `Alt+글자`, `Ctrl+Shift+글자`, `Ctrl+Shift+숫자`, `F1`–`F10`
- 브라우저·OS가 가져가는 조합(`Ctrl+W`, `F12`, `Ctrl+숫자` 등)과 한/영 전환, 편집 단축키는 **자동으로 거부**되고 이유를 알려준다
- 핫키는 **바로 전송되지 않고 입력창에 삽입**된다. 이어붙여 쓰고 `Enter`로 확정한다
- **핫키는 브라우저에 저장되므로 속기사마다 자기 세트를 갖는다**

### 협업

- 상대가 입력 중인 내용이 `실시간 모니터링` 영역에 그대로 보인다 → 중복 입력 방지
- 상대가 입력 중이면 내 `전송` 버튼이 노랗게 바뀐다 (경고일 뿐 전송은 막지 않는다)
- 히스토리에서 **내 것은 파랑 `나` 칩, 상대 것은 보라 이름 칩**으로 구분된다
- 상대가 방을 나가면 접속자 패널 전체가 빨갛게 깜빡인다 — 혼자 치고 있는 걸 모르면 안 되므로

## 5. 송출 화면을 스위처에 물리기

### 기본 방식 (크로마키)

1. 송출용 화면을 브라우저로 열고 `F11`로 전체화면
2. OBS 등으로 그 창을 캡처해 가상카메라로 내보냄
3. 스위처에서 크로마키 색(기본 `#00FF00`)을 지정해 투명 처리

### 설정은 URL로 고정한다 — 중요

**스위처에 URL만 넣는 방식이라면 페이지 안의 설정 패널을 건드릴 수 없다.**
그래서 모든 설정값을 URL 파라미터로 표현할 수 있게 만들어 두었다.

1. 내 PC에서 송출 화면을 열고 우상단 `⚙` → 폰트·색·줄 수를 원하는 대로 맞춘다
2. 패널 하단에 **완성된 URL이 실시간으로 생성**된다
3. `URL 복사`를 눌러 스위처에 붙여넣는다

```
/broadcast?lang=ko&fontSize=64&maxLines=3&minDurationMs=3000&safeArea=1080
```

우선순위는 **URL > localStorage > config.json 기본값**이다.

### 글자 가장자리에 녹색이 번질 때

브라우저 → 가상카메라 경로는 대개 색상 정보를 압축(4:2:0)하기 때문에 흰 글자와 녹색 배경 사이가 번진다.

- **검정 외곽선을 기본으로 켜 두었다.** 흰 글자와 녹색 사이의 완충층 역할을 한다
- 그래도 번지면 설정에서 `외곽선`을 2px → **3~4px**로 올린다
- 배경색은 자유롭게 바꿀 수 있다. 출연자 의상이 녹색이면 마젠타(`#FF00FF`) 등으로 교체

### 창 크기가 달라져도 자막 위치를 고정하려면

`캔버스` 설정을 `1920×1080 고정`으로 두면 창 크기와 무관하게 자막 위치가 유지된다.
가상카메라로 캡처할 때는 사실상 필수다.

### 자막이 쌓이는 방식

- 기본 2줄. 입력이 몰리면 최대 4줄까지 확장
- 새 자막이 아래에 붙고 오래된 것이 위로 밀려 사라진다
- `최소 노출` 시간 동안은 자막이 사라지지 않는다. 단 4줄을 넘겨 밀려나는 경우는 예외 (큐가 막히면 안 되므로)
- 입력이 멈추면 `축소 대기` 시간 뒤 오래된 것부터 사라진다

## 6. 현장 운영 체크리스트

**방송 전**

- [ ] 서버 PC에서 `npm start`, 콘솔의 외부 접속 주소 확인
- [ ] 속기사 PC들에서 그 주소로 접속, 각자 **이름을 서로 다르게** 설정
- [ ] 송출 화면을 스위처에 물리고 크로마키 확인
- [ ] 속기사 화면 상단이 `ON AIR`인지 확인 (송출 화면이 붙어야 켜진다)
- [ ] 딜레이 값 합의
- [ ] 시험 자막 1~2줄 보내고 실제로 화면에 나오는지 확인 후 `Esc`로 비우기

**방송 중 문제 대응**

| 증상 | 원인 / 대처 |
|---|---|
| 상단이 `연결 없음` | 서버가 꺼졌다. `npm start` 재실행. 그동안 친 자막은 빨간 `전송 실패`로 남고, 복구 후 `재전송` 누르면 나간다 |
| 상단이 `OFF AIR` | 송출 화면이 안 붙어 있다. 송출용 URL을 다시 연다 |
| 자막이 화면에 안 보임 | 송출 화면 새로고침. 최근 4줄이 자동 복구된다 |
| 오타가 화면에 박혔다 | `Ctrl+Backspace` (내 마지막 것) 또는 히스토리에서 `회수` |
| 자막을 전부 내려야 한다 | `Esc` (입력창이 비어 있을 때) 또는 `화면 비우기` 버튼. **대기 중인 것까지 전부 취소된다** |
| 두 사람이 같은 이름 | 접속자 뱃지가 주황으로 바뀐다. 이름을 클릭해 변경 |

**서버 PC는 절대 끄거나 재부팅하지 않는다.** 서버가 죽으면 모든 화면이 멈춘다.

## 7. 테스트

```bash
npm run smoke          # 서버 릴레이 18개 항목 (서버가 떠 있어야 함)
npm run test:hotkeys   # 핫키 충돌 규칙 44개 케이스
```

`npm run smoke`는 실행 중 브라우저 탭이 같은 방에 붙어 있으면 접속자 수가 흔들려 실패할 수 있다. 탭을 닫고 실행한다.

## 8. 아직 안 된 것

- **영상 플레이어** — RTMP/SRT 연동 미구현. 현재는 빈 자리이며 `?video=<url>`로 iframe만 삽입 가능
- **기계 번역** — 마스터 언어 → 타 언어 자동 번역 미구현 (훅만 있음)
- **인증 없음** — 같은 네트워크에 있으면 누구나 접속해 자막을 보낼 수 있다. **사내망 전용으로만 쓸 것**
- **인터넷 배포 미대응** — 원격 속기사가 필요하면 HTTPS와 인증을 먼저 붙여야 한다
